## 離線開啟

1. 下載 [`portable/裝修設備規劃.html`](portable/裝修設備規劃.html) 與 [`files/設備規劃.json`](files/設備規劃.json)，放在自己的電腦上。
2. 用最新版 Chrome 或 Edge 雙擊 HTML，按「**讀檔 JSON**」選擇示例存檔。可瀏覽房間與門窗示意、拖放設備、修改商品、試算價格，並輸出清單 CSV。
3. 修改後按「**存檔 JSON**」取得新版存檔；瀏覽器的本機暫存不能代替存檔。離線 HTML **不內嵌**設備 JSON，首次開啟須自行讀入；不需要伺服器或網路。

示例 JSON 是 **v5**，含 13 個空間、182 個物件、28 款商品、獨立的開工行事曆及管委會清潔費；原有匿名物件 ID 與商品連動均保留。設備修訂版次為 0、`undo` 為 `null`，未附先前編輯紀錄；行事曆與清潔費各有自己的單步復原欄位。清潔費的 `undo: {fee: null}` 只表示這份公開草稿可還原到「未設定」，不是個人舊編輯紀錄。日後自己匯出的 JSON 可能包含新輸入的私人資料與復原點，分享前請另行檢查。

## 開工行事曆：可離線編輯的暫排草稿

同一個規劃器最右側新增「**開工行事曆**」分頁；本公開匿名示例**僅以經使用者允許的施工日期／工項**建立 13 筆**暫排**工作，不含個人行事曆或任何截圖影像／位元組。格線按台北日期、週日為每週起點；每個週日（含相鄰月份格）標示「師傅固定休假」，**多日工項的顯示條在週日中斷、週一續畫**，週六及其他假日不自動跳過。工項儲存的開始與結束日、復原紀錄及清單／CSV 的**原始含首尾日期不變**，不因週日而順延完工；自行新增的**週日單日工項**仍顯示並標記「週日例外安排」。預設為單月檢視；「**完整展開**」依實際工項起迄月份顯示上下排列的月份（本例 2026/10～2027/01 共四個月），手機上每張格線可獨立左右捲動，並非甘特圖。超過 24 個月會提示完整起迄及上限，不顯示截短的月份；切換檢視不複製工項或寫入資料。文字清單列完整日期與工項；所有工項都可以新增、改期、更名、刪除、標記「已確認（使用者標記）」並用「還原日曆上一步」復原。**這只是示例顯示規則，不是承包商排程或施工承諾；「已確認」也只是使用者自己的標記**，實際休工、施工順序、請料、合約與完工點交須另核對。

台灣政府辦公日曆假日／補假、節氣與繁體農曆僅核對 **2026-09-01～2027-03-31**；1 月末相鄰格亦顯示 **2027-02-05 除夕、02-06 春節初一**。核對範圍外的空白**不代表工作日**，農曆會使用瀏覽器的台北時區中國曆而非假裝已逐日核對；政府辦公日曆也不決定私人施工是否休工。行事曆完全離線計算，不串接 Google 帳戶／日曆、沒有外部 API；來源連結只有手動點擊才開啟。

編輯工項另存於頂層 `constructionCalendar`（本例 **v2**，每筆必有角色清單）；**未含管理費時**以 JSON 容器 **10** 匯出，含獨立管理費的目前示例則用容器 **11**。未含角色的行事曆 **v1／容器 9** 與更早存檔仍可匯入。工項 CSV 與設備、清潔費 CSV 分開下載。日曆與設備**各有獨立單步 Undo**：改工期或角色不更改房間／物件／報價、控制配對或設備的 Undo。從容器 9 舊檔匯入已含角色的目前存檔時，相同工項 ID 的現有角色保留，其他工項仍為「未指定」。新版寫入器須帶 `calendarAttendeesVersion: 1`，舊版不能抹掉角色或角色復原點。

先前離線角色版 key `renovation-equipment-offline-calendar-attendees-v1` 依序接續舊行事曆、機器人、門片、控制及原始版快取。本版新增費用專用 key `renovation-equipment-offline-management-fee-v1`，**僅在自身不存在時**優先複製角色版，再依序核對上述舊 key；保留每個原 key，其後只使用費用版 key。**舊瀏覽器的 179／180／181／182 筆個人編輯及既有日曆優先，不自動植入 13 筆草稿、角色或清潔費**；想看新版請先下載自己的 JSON 備份，再用乾淨瀏覽器開啟或手動匯入匿名示例。損壞的新 key 會報錯，不會默默回退較舊資料。頂層設備樣本維持 v5 `revision: 0`、`undo: null`；不含新增清潔費時原報價 **NT$1,959,530** 與物件已知暫計 **NT$2,322,060.20** 不因日曆或角色而變動。

## 原始碼與重建

`extensions/renovation-equipment/assets/` 是共用的規劃器介面及幾何／預算邏輯，`extensions/renovation-equipment/state.mjs` 負責驗證存檔；`tools/portable-bootstrap.js` 將相同模組接入瀏覽器本機儲存。`extensions/renovation-equipment/extension.mjs` 是在提供 `@github/copilot-sdk/extension` 的 Copilot App 環境中使用的可選畫布入口，不是離線使用的必要條件。

在此目錄執行 `python tools\build_portable.py` 即可用 Python 標準函式庫重建 [`portable/裝修設備規劃.html`](portable/裝修設備規劃.html)；建置會拒絕靜態圖片或 PDF 參照，不讀取原始文件。執行 `python -m unittest discover -s tests -v` 可檢查公開存檔、報價基準與單檔產物。若已安裝 Chrome 和 Python Playwright，可先在 PowerShell 設定 `$env:RUN_PAGES_BROWSER_TESTS = "1"`，再執行同一測試指令；測試會用本機 HTTP 伺服器模擬 Pages 子路徑、存檔衝突及離線行為。公開版不附原始文件、個人檔案或任何私人儲存庫的 Git 歷史。

若已安裝 Node.js，可用 `node --test tools\test_control_relations.mjs` 檢查面板關聯、JSON 容器與舊版寫入防護；安裝 Python Playwright 與 Edge 後，以 `python tools\test_control_relations_browser.py <node.exe> <暫存截圖目錄>` 驗證獨立臨時 HTTP store、離線版與舊瀏覽器暫存複製。該測試只修改臨時資料檔及指定截圖目錄，不修改公開示例 JSON。
